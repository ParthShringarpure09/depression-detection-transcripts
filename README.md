# Punctual or Continuous? Segmentation Granularity and the Combination of Segment-Level Evidence in Linguistic Depression Detection

Code for the MSc dissertation of the same name (University of Glasgow, School of Computing Science, September 2026).

The study asks whether depression-related linguistic evidence is **punctual** (concentrated in a few passages of an interview) or **continuous** (distributed across it). The 116 spontaneous interviews of the Androids Corpus are transcribed with Whisper, split into N contiguous segments for N in {1, 2, 4, 8, 16, 32, 64}, and represented with contextual embeddings from an Italian BERT model. Three ways of combining segment-level evidence are compared at every granularity — majority voting, max-pooling (selection) and mean-pooling (aggregation) — each in a neural and a linear classifier, under the person-independent five-fold protocol distributed with the corpus.

Best result: **F1 = 92.8%** for the Depression class using transcripts alone (MINN with aggregation at N=8).

## Data

The Androids Corpus is **not** redistributed here. It is publicly available from its authors (Tao et al., Interspeech 2023). Only the **Interview Task** is used.

Place it as follows, then run the pipeline from `src/`:

```
data/Androids-Corpus/
├── Interview-Task/audio/HC/*.wav
├── Interview-Task/audio/PT/*.wav
└── fold-lists.csv          # official five-fold speaker assignment
```

`HC` = control, `PT` = diagnosed with depression. All notebook paths are relative to `src/`.

## Running the pipeline

Run the notebooks in the order above.

1. **Transcription** — `transcribe.ipynb` is written for Google Colab: mount Drive, unzip the corpus, run Whisper `large-v3` with the language forced to Italian. Writes one `.txt` (plain transcript) and one `.json` (timestamped utterances) per interview. Update `DRIVE_ZIP_PATH` and `OUTPUT_DIR` before running, then copy the transcripts back into `transcripts/`.
2. **Segmentation** — splits each transcript into N contiguous, near-equal parts by word count at all seven levels, producing 127 files per speaker named `<speaker>_N<N>_seg<k>.txt`. Includes a check that the segments reconstruct the original transcript exactly.
3. **Feature extraction** — encodes each segment with `dbmdz/bert-base-italian-xxl-cased`, mean-pooling the final hidden layer over all token positions into a 768-dim vector saved as `.npy`. Also reports how much input is truncated at the 510-token content budget (only N=1 and N=2 are affected).
4. **Classification** — six configurations across seven granularities. Neural runs use seeds 0–4; linear models are deterministic and run once per fold. Each notebook writes a JSON summary under `Models/`.
5. **Analysis** — `results.ipynb` loads every result file, checks that all methods have five per-fold F1s at all seven N-levels, and produces the paired t-tests, comparison tables and figures reported in the dissertation.

### Result files consumed by `results.ipynb`

| Path | Contents |
| --- | --- |
| `Models/FFNN_R5/results_sil_folds.json` | FFNN + majority vote |
| `Models/Linear_baseline/results_linear_folds.json` | Logistic Regression and Linear SVM + majority vote |
| `Models/MIL/results_minn_pooled.json` | MINN, `max` and `mean` pooling |
| `Models/MIL_Linear/results_summary.json` | Pooled embeddings + Logistic Regression, `max` and `mean` |

Each classification folder also contains a `results_summary.json` from an earlier pass that stored fold means and standard deviations only. Those are superseded by the `*_folds.json` files above, which keep the five per-fold F1 scores needed for the paired significance tests — except in `MIL_Linear/`, where `results_summary.json` is itself the per-fold file.

## Experimental settings

| Setting | Value |
| --- | --- |
| Language model | `dbmdz/bert-base-italian-xxl-cased`, frozen (no fine-tuning) |
| Embedding | 768-dim, mean over final hidden layer, max 512 tokens |
| Segmentation | N in {1, 2, 4, 8, 16, 32, 64}, by word count |
| Encoder (FFNN / MINN) | 3 hidden layers, 32 / 64 / 128 units, ReLU; sigmoid output |
| Training | Adam, lr 0.001, 30 epochs, BCE loss; batch 32 (SIL), one bag per step (MIL) |
| Repetitions | R = 5, seeds 0–4 (neural only) |
| MIL pooling | max or mean over 128-dim hidden representations |
| Logistic Regression | C = 1.0, max 1,000 iterations, no standardisation |
| Linear SVM | C = 1.0, max 5,000 iterations, `dual="auto"`, seed not fixed |
| Cross-validation | Person-independent five-fold, corpus-supplied folds |
| Tie-breaking | Majority-vote ties resolved in favour of Control |
| Metric | F1 for the Depression class (majority-class floor: 71.1%) |

## Reproducibility notes

- Seeds fix both weight initialisation and shuffling order, and all classification runs on CPU, so every reported neural run reproduces exactly.
- The Linear SVM uses a randomised solver without a fixed seed, so its numbers are not deterministic. Its N=64 row is flagged as unverified in Appendix A.1 of the dissertation.
- Folds are defined over speakers, never segments. `data_utils.py` derives the speaker-to-fold mapping from `fold-lists.csv` (Interview-Task columns 7–11) and the segment-to-speaker mapping from filenames, so no speaker can appear in both partitions of a split.
- The folds are unstratified: fold 4 holds 18 depressed against 5 control participants, which drives much of the cross-fold variance.

## Known limitations

- Transcripts are not speaker-separated, so they include the interviewer's speech. Its share differs between groups, so it cannot be assumed neutral. The corpus distributes turn-level segmentation that would allow it to be removed.
- Transcription accuracy was not measured against reference transcripts; the word error rate is unknown.
- Segments at N=1 and N=2 exceed BERT's 510-token content budget and are truncated (26.2% and 2.3% of tokens respectively), so N=1 is an imperfect reference point for the degradation analysis.
